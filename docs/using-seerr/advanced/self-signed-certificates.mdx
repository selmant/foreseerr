# Self-Signed Certificates

If your media server or services (Radarr, Sonarr, etc.) use self-signed SSL certificates, Foreseerr will reject the connection because it does not trust them by default. The fix is to tell Foreseerr to trust your CA certificate.

## Add Your CA Certificate

The `NODE_EXTRA_CA_CERTS` environment variable names a PEM file of additional Certificate Authority (CA) certificates for Foreseerr to trust on its outgoing connections, on top of the built-in ones. The name is kept from Foreseerr's earlier Node.js backend, so existing setups keep working. This approach keeps certificate validation active while trusting your specific certificate.

You will need to mount your certificate file (in PEM format) into the container and set the environment variable to point to it.

:::note
These examples show only the certificate-related configuration. For a complete setup, see the [Getting Started](/getting-started) guide.
:::

<Tabs>
<TabItem value="docker-cli" label="Docker CLI">

```bash
docker run -d \
  --name foreseerr \
  -e NODE_EXTRA_CA_CERTS=/certs/my-ca.pem \
  -v /path/to/my-ca.pem:/certs/my-ca.pem:ro \
  -p 5055:5055 \
  ghcr.io/selmant/foreseerr:latest
```

</TabItem>
<TabItem value="docker-compose" label="Docker Compose">

```yaml
services:
  foreseerr:
    image: ghcr.io/selmant/foreseerr:latest
    environment:
      - NODE_EXTRA_CA_CERTS=/certs/my-ca.pem
    volumes:
      - /path/to/my-ca.pem:/certs/my-ca.pem:ro
    ports:
      - 5055:5055
```

</TabItem>
</Tabs>

Replace `/path/to/my-ca.pem` with the actual path to your CA certificate on the host. The path after the colon (`/certs/my-ca.pem`) is where it will be available inside the container.

:::tip
The certificate must be in PEM format. Open it in a text editor — if it starts with `-----BEGIN CERTIFICATE-----`, it is PEM. If it contains binary data, convert it with `openssl x509 -inform DER -in cert.cer -out cert.pem`.
:::

The file may hold several certificates one after another. Restart Foreseerr after changing it.
